- 클라우드 컴퓨팅이란?
    
    # 클라우드 컴퓨팅(Cloud Computing)이란?
    
    ## 1. 개념
    
    클라우드 컴퓨팅(Cloud Computing)이란 인터넷을 통해 서버, 저장소(Storage), 데이터베이스, 네트워크, 소프트웨어 등의 IT 자원을 필요한 만큼 제공받아 사용하는 기술이다.
    
    기존에는 기업이나 개인이 직접 서버를 구매하고 관리해야 했지만, 클라우드 컴퓨팅에서는 서비스 제공업체가 구축한 자원을 인터넷을 통해 빌려 사용할 수 있다.
    
    즉, 사용자는 물리적인 하드웨어를 직접 관리하지 않고도 원하는 컴퓨팅 자원을 사용할 수 있다.
    
    ---
    
    ## 2. 특징
    
    ### ① 온디맨드(On-Demand) 서비스
    
    사용자가 필요한 시점에 필요한 만큼 자원을 사용할 수 있다.
    
    ### ② 확장성(Scalability)
    
    사용량 증가에 따라 서버 자원을 쉽게 늘리거나 줄일 수 있다.
    
    ### ③ 비용 절감
    
    직접 서버를 구매하지 않고 사용한 만큼만 비용을 지불한다.
    
    ### ④ 높은 가용성
    
    서비스 제공업체가 서버를 관리하므로 안정적인 서비스 운영이 가능하다.
    
    ### ⑤ 접근성
    
    인터넷만 연결되어 있다면 언제 어디서든 자원에 접근할 수 있다.
    
    ---
    
    ## 3. 서비스 유형
    
    ### ① IaaS (Infrastructure as a Service)
    
    서버, 스토리지, 네트워크 등 IT 인프라를 제공하는 서비스
    
    - 사용자는 운영체제 및 애플리케이션을 직접 관리
    - 예시
        - AWS EC2
        - Google Compute Engine
        - Microsoft Azure VM
    
    ### ② PaaS (Platform as a Service)
    
    애플리케이션 개발 및 배포 환경을 제공하는 서비스
    
    - 개발자는 인프라 관리 없이 개발에 집중 가능
    - 예시
        - Google App Engine
        - Heroku
    
    ### ③ SaaS (Software as a Service)
    
    소프트웨어를 인터넷을 통해 제공하는 서비스
    
    - 별도 설치 없이 웹 브라우저로 사용 가능
    - 예시
        - Google Docs
        - Gmail
        - Microsoft 365
    
    ---
    
    ## 4. 대표적인 클라우드 서비스
    
    - AWS (Amazon Web Services)
    - Google Cloud Platform (GCP)
    - Microsoft Azure
    - Naver Cloud Platform (NCP)
    
    ---
    
    ## 5. 클라우드 컴퓨팅의 장점
    
    - 초기 구축 비용 감소
    - 유지보수 부담 감소
    - 빠른 서비스 배포 가능
    - 높은 확장성 제공
    - 안정적인 데이터 관리 가능
    
    ---
    
    ## 6. 클라우드 컴퓨팅의 단점
    
    - 인터넷 연결이 필수적
    - 서비스 장애 시 영향 발생 가능
    - 보안 및 개인정보 관리에 대한 고려 필요
    - 장기적으로 사용량이 많을 경우 비용 증가 가능
    
    ---
    
    ## 7. 정리
    
    클라우드 컴퓨팅은 서버와 같은 IT 자원을 인터넷을 통해 제공받아 사용하는 기술이다. 사용자는 직접 하드웨어를 관리할 필요 없이 필요한 자원을 필요한 만큼 사용할 수 있으며, 비용 절감과 높은 확장성이라는 장점을 가진다. 현재 AWS, GCP, Azure 등의 플랫폼을 중심으로 다양한 분야에서 활용되고 있다.

    # AWS와 GCP란?
    
    ## 1. 개요
    
    AWS(Amazon Web Services)와 GCP(Google Cloud Platform)는 대표적인 클라우드 컴퓨팅 플랫폼이다.
    
    클라우드 컴퓨팅은 서버, 데이터베이스, 스토리지, 네트워크 등의 IT 자원을 인터넷을 통해 제공하는 기술이며, AWS와 GCP는 이러한 자원을 사용자가 필요할 때 언제든지 사용할 수 있도록 제공한다.
    
    개발자는 직접 서버를 구매하거나 관리하지 않고도 애플리케이션을 개발하고 운영할 수 있으며, 사용한 만큼 비용을 지불하는 방식(Pay-As-You-Go)을 주로 사용한다.
    
    ---
    
    # 2. AWS (Amazon Web Services)
    
    ## AWS란?
    
    AWS는 아마존(Amazon)에서 제공하는 세계 최대 규모의 클라우드 서비스 플랫폼이다.
    
    2006년에 출시되었으며 현재 가장 높은 시장 점유율을 가지고 있다.
    
    스타트업부터 대기업, 공공기관까지 다양한 조직에서 AWS를 사용하고 있다.
    
    ---
    
    ## AWS의 주요 서비스
    
    ### ① EC2 (Elastic Compute Cloud)
    
    가상 서버를 생성하고 운영할 수 있는 서비스
    
    - 서버 구축 가능
    - 운영체제 선택 가능
    - CPU, 메모리 자유롭게 설정 가능
    
    예시
    
    - Spring 서버 배포
    - Node.js 서버 배포
    - Django 서버 운영
    
    ---
    
    ### ② S3 (Simple Storage Service)
    
    파일 저장 서비스
    
    - 이미지 저장
    - 동영상 저장
    - 백업 데이터 저장
    
    특징
    
    - 높은 내구성
    - 무제한에 가까운 저장 공간
    - 정적 웹사이트 호스팅 가능
    
    ---
    
    ### ③ RDS (Relational Database Service)
    
    관계형 데이터베이스 서비스
    
    지원 DB
    
    - MySQL
    - PostgreSQL
    - MariaDB
    - Oracle
    - SQL Server
    
    개발자가 직접 DB 서버를 관리하지 않아도 된다.
    
    ---
    
    ### ④ Lambda
    
    서버리스(Serverless) 서비스
    
    서버를 직접 구축하지 않고 코드를 실행할 수 있다.
    
    특징
    
    - 사용한 만큼만 비용 지불
    - 자동 확장
    - 이벤트 기반 실행
    
    ---
    
    ### ⑤ CloudFront
    
    콘텐츠 전송 네트워크(CDN)
    
    전 세계 사용자에게 빠르게 콘텐츠를 전달할 수 있다.
    
    ---
    
    ## AWS의 장점
    
    - 가장 많은 서비스 제공
    - 풍부한 문서와 학습 자료
    - 높은 시장 점유율
    - 다양한 기업에서 사용
    - 강력한 확장성
    
    ## AWS의 단점
    
    - 서비스 종류가 많아 학습 난이도가 높음
    - 비용 구조가 복잡함
    - 초보자에게 다소 어려울 수 있음
    
    ---
    
    # 3. GCP (Google Cloud Platform)
    
    ## GCP란?
    
    GCP는 구글(Google)이 제공하는 클라우드 플랫폼이다.
    
    구글 검색, 유튜브, Gmail 등 대규모 서비스를 운영하며 축적한 인프라 기술을 기반으로 만들어졌다.
    
    특히 데이터 분석, 인공지능(AI), 머신러닝 분야에서 강점을 가진다.
    
    ---
    
    ## GCP의 주요 서비스
    
    ### ① Compute Engine
    
    AWS의 EC2와 비슷한 가상 서버 서비스
    
    - Linux 서버 운영
    - Windows 서버 운영
    - 웹 서버 배포
    
    ---
    
    ### ② Cloud Storage
    
    AWS S3와 유사한 저장소 서비스
    
    - 이미지 저장
    - 파일 저장
    - 백업 데이터 관리
    
    ---
    
    ### ③ Cloud SQL
    
    관리형 데이터베이스 서비스
    
    지원 DB
    
    - MySQL
    - PostgreSQL
    - SQL Server
    
    ---
    
    ### ④ BigQuery
    
    GCP의 대표 서비스
    
    대규모 데이터를 매우 빠르게 분석할 수 있는 데이터 웨어하우스 서비스이다.
    
    특징
    
    - 빅데이터 처리
    - 데이터 분석
    - 통계 분석
    
    ---
    
    ### ⑤ Vertex AI
    
    인공지능 및 머신러닝 플랫폼
    
    특징
    
    - AI 모델 학습
    - AI 모델 배포
    - 생성형 AI 활용
    
    ---
    
    ## GCP의 장점
    
    - 데이터 분석 기능이 강력함
    - AI 및 머신러닝 서비스 우수
    - 직관적인 인터페이스
    - Google 서비스와 연동이 쉬움
    
    ## GCP의 단점
    
    - AWS보다 사용자 수가 적음
    - 국내 자료가 상대적으로 적음
    - 일부 서비스 생태계가 AWS보다 작음
    
    ---
    
    # 4. AWS와 GCP 비교
    
    | 항목 | AWS | GCP |
    | --- | --- | --- |
    | 운영 회사 | Amazon | Google |

    # 5. 정리
    
    AWS와 GCP는 대표적인 클라우드 플랫폼으로, 서버와 데이터베이스 같은 IT 자원을 인터넷을 통해 제공한다.
    
    AWS는 가장 높은 시장 점유율과 다양한 서비스를 제공하며, GCP는 데이터 분석과 AI 분야에서 강점을 가진다.
    
    백엔드 개발자는 AWS의 EC2, S3, RDS와 같은 서비스를 자주 사용하며, 최근에는 GCP의 BigQuery와 Vertex AI 역시 많이 활용되고 있다.

    # 환경변수 처리 방법과 왜 환경변수로 민감 정보를 가려야 하는가?
    
    ## 환경변수(Environment Variable)란?
    
    환경변수는 프로그램 실행에 필요한 설정값을 코드 외부에서 관리하는 방법이다.
    
    애플리케이션은 실행 과정에서 데이터베이스 정보, API 키, 포트 번호 등의 다양한 설정값이 필요한데, 이러한 값을 코드에 직접 작성하지 않고 환경변수로 분리하여 관리할 수 있다.
    
    예를 들어 데이터베이스 연결에 필요한 정보는 다음과 같다.
    
    - DB 주소
    - DB 사용자명
    - DB 비밀번호
    - 포트 번호
    
    이러한 정보들을 환경변수로 관리하면 코드와 설정을 분리할 수 있다.
    
    ---
    
    ## 환경변수 처리 방법
    
    ### 1. 환경변수 직접 사용
    
    운영체제에 환경변수를 등록한 후 프로그램에서 읽어오는 방법이다.
    
    예시
    
    ```java
    String dbPassword = System.getenv("DB_PASSWORD");
    ```
    
    프로그램은 실행 시 운영체제에 등록된 환경변수 값을 가져와 사용한다.
    
    ---
    
    ### 2. .env 파일 사용
    
    프로젝트 루트에 `.env` 파일을 생성하여 환경변수를 관리할 수 있다.
    
    예시
    
    ```
    DB_HOST=localhost
    DB_USERNAME=root
    DB_PASSWORD=1234
    JWT_SECRET=my-secret-key
    ```
    
    애플리케이션은 해당 파일을 읽어 필요한 값을 가져와 사용한다.
    
    ---
    
    ### 3. Spring Boot에서 사용
    
    Spring Boot에서는 yml 파일과 환경변수를 함께 사용할 수 있다.
    
    ```yaml
    spring:
      datasource:
        username: ${DB_USERNAME}
        password: ${DB_PASSWORD}
    ```
    
    실제 값은 환경변수에서 가져오며, yml 파일에는 변수명만 작성한다.
    
    ---
    
    ## 민감 정보란?
    
    민감 정보(Sensitive Information)는 외부에 노출될 경우 보안 문제가 발생할 수 있는 정보를 의미한다.
    
    대표적인 예시는 다음과 같다.
    
    - 데이터베이스 비밀번호
    - API Key
    - JWT Secret Key
    - AWS Access Key
    - OAuth Client Secret
    
    이러한 정보가 유출되면 데이터베이스 접근, 서버 조작, 개인정보 유출 등의 문제가 발생할 수 있다.
    
    ---
    
    ## 왜 환경변수로 민감 정보를 관리해야 할까?
    
    ### 1. GitHub 노출 방지
    
    비밀번호나 API Key를 코드에 직접 작성하면 GitHub에 업로드될 위험이 있다.
    
    잘못된 예시
    
    ```java
    String password = "1234";
    ```
    
    위와 같은 방식은 소스 코드가 공개될 경우 비밀번호도 함께 노출된다.
    
    반면 환경변수를 사용하면 코드에는 실제 값이 존재하지 않는다.
    
    ```java
    String password = System.getenv("DB_PASSWORD");
    ```
    
    ---
    
    ### 2. 보안성 향상
    
    민감한 정보를 코드와 분리하면 접근 권한이 있는 사용자만 해당 정보를 확인할 수 있다.
    
    따라서 비밀번호나 인증 키가 외부에 노출될 가능성을 줄일 수 있다.
    
    ---
    
    ### 3. 환경별 설정 관리
    
    개발 환경과 운영 환경은 서로 다른 설정값을 사용한다.
    
    예를 들어 개발 환경에서는 테스트용 데이터베이스를 사용하고, 운영 환경에서는 실제 데이터베이스를 사용한다.
    
    환경변수를 사용하면 코드 수정 없이 환경에 맞는 설정을 적용할 수 있다.
    
    ---
    
    ### 4. 유지보수 편의성
    
    비밀번호가 변경되더라도 코드를 수정할 필요가 없다.
    
    환경변수 값만 변경하면 되기 때문에 관리가 훨씬 편리하다.
    
    ---
    
    ## .gitignore와 함께 사용하기
    
    `.env` 파일에는 민감 정보가 포함될 수 있으므로 Git에 업로드하지 않는 것이 중요하다.
    
    따라서 `.gitignore`에 등록하여 관리한다.
    
    ```
    .env
    .env.*
    ```
    
    이를 통해 실수로 GitHub에 업로드되는 것을 방지할 수 있다.
    
    ---
    
    ## 정리
    
    환경변수는 프로그램 실행에 필요한 설정값을 코드 외부에서 관리하는 방법이다. 특히 데이터베이스 비밀번호, API Key, JWT Secret Key와 같은 민감 정보는 코드에 직접 작성하지 않고 환경변수로 관리하는 것이 중요하다. 이를 통해 보안성을 높이고, 환경별 설정을 효율적으로 관리하며, 유지보수를 더욱 편리하게 할 수 있다.

    # yml 환경 분리 방법
    
    ## yml 환경 분리란?
    
    Spring Boot 프로젝트는 개발 환경(Local), 테스트 환경(Test), 운영 환경(Production)마다 서로 다른 설정을 사용한다.
    
    예를 들어 개발 환경에서는 로컬 데이터베이스를 사용하지만, 운영 환경에서는 실제 서비스용 데이터베이스를 사용한다.
    
    이처럼 환경마다 다른 설정을 효율적으로 관리하기 위해 yml 파일을 환경별로 분리하여 사용한다.
    
    ---
    
    ## 환경 분리가 필요한 이유
    
    만약 모든 설정을 하나의 파일에 작성한다면 환경이 바뀔 때마다 직접 수정해야 한다.
    
    예를 들어 데이터베이스 주소를 변경해야 하는 경우 실수로 운영 서버 설정을 수정하거나 중요한 정보를 노출할 위험이 있다.
    
    환경별 설정 파일을 분리하면 코드 수정 없이 환경에 맞는 설정을 선택하여 실행할 수 있다.
    
    ---
    
    ## Spring Profile
    
    Spring Boot에서는 Profile 기능을 통해 환경을 구분한다.
    
    대표적으로 다음과 같은 Profile을 사용한다.
    
    - local : 개발 환경
    - dev : 개발 서버 환경
    - prod : 운영 환경
    
    각 Profile마다 별도의 yml 파일을 만들어 관리할 수 있다.
    
    ---
    
    ## yml 파일 구성 예시
    
    ```
    src/main/resources
    
    ├── application.yml
    ├── application-local.yml
    ├── application-dev.yml
    └── application-prod.yml
    ```
    
    ---
    
    ## application.yml
    
    공통 설정을 작성하거나 활성화할 Profile을 지정하는 파일이다.
    
    ```yaml
    spring:
      profiles:
        active: local
    ```
    
    위 설정은 local 환경을 활성화한다는 의미이다.
    
    ---
    
    ## 환경별 설정 파일
    
    ### application-local.yml
    
    ```yaml
    spring:
      datasource:
        url: jdbc:mysql://localhost:3306/umc
    ```
    
    ### application-dev.yml
    
    ```yaml
    spring:
      datasource:
        url: jdbc:mysql://dev-db.example.com:3306/umc
    ```
    
    ### application-prod.yml
    
    ```yaml
    spring:
      datasource:
        url: jdbc:mysql://prod-db.example.com:3306/umc
    ```
    
    같은 코드라도 활성화된 Profile에 따라 다른 설정이 적용된다.
    
    ---
    
    ## 환경변수와 함께 사용하기
    
    비밀번호나 API Key와 같은 민감 정보는 yml 파일에 직접 작성하지 않고 환경변수와 함께 사용하는 것이 좋다.
    
    ```yaml
    spring:
      datasource:
        password: ${DB_PASSWORD}
    ```
    
    이렇게 하면 설정 파일이 외부에 공개되더라도 민감 정보가 노출되지 않는다.
    
    ---
    
    ## yml 환경 분리의 장점
    
    ### 1. 환경별 설정 관리가 쉽다.
    
    개발 환경과 운영 환경을 독립적으로 관리할 수 있다.
    
    ### 2. 유지보수가 편리하다.
    
    환경 설정 변경 시 코드 수정 없이 설정 파일만 변경하면 된다.
    
    ### 3. 보안성이 향상된다.
    
    환경변수와 함께 사용하여 민감 정보를 안전하게 관리할 수 있다.
    
    ### 4. 배포가 편리하다.
    
    같은 애플리케이션을 여러 환경에서 쉽게 실행할 수 있다.
    
    ---
    
    ## 정리
    
    Spring Boot에서는 Profile 기능을 활용하여 환경별 yml 파일을 분리할 수 있다. 이를 통해 개발 환경과 운영 환경의 설정을 독립적으로 관리할 수 있으며, 유지보수성과 보안성을 높일 수 있다. 실무에서는 환경변수와 함께 사용하여 민감 정보를 보호하는 방식이 일반적으로 사용된다.
    
- Docker와 .jar vs Docker 이미지
    
    # Docker와 .jar, Docker Image의 차이
    
    ## Docker란?
    
    Docker는 애플리케이션을 실행하는 데 필요한 환경을 하나의 컨테이너로 묶어 배포할 수 있도록 해주는 플랫폼이다.
    
    프로그램을 개발한 환경과 실제 서버 환경이 다를 경우 실행 오류가 발생할 수 있는데, Docker를 사용하면 개발 환경과 동일한 환경을 유지한 채 배포할 수 있다.
    
    즉, "어디서 실행하더라도 동일하게 동작하는 환경"을 만드는 것이 Docker의 핵심 목적이다.
    
    ---
    
    ## Docker의 주요 개념
    
    ### Image
    
    Docker Image는 컨테이너를 생성하기 위한 설계도와 같은 역할을 한다.
    
    운영체제, 라이브러리, 애플리케이션 실행 정보 등이 포함되어 있으며 실행되기 전의 정적인 상태이다.
    
    ---
    
    ### Container
    
    Docker Container는 이미지를 실제로 실행한 상태이다.
    
    하나의 이미지로 여러 개의 컨테이너를 생성할 수 있으며, 각각 독립적으로 동작한다.
    
    ---
    
    ## .jar 파일이란?
    
    .jar(Java Archive) 파일은 Java 애플리케이션을 실행하기 위해 필요한 클래스 파일과 라이브러리를 하나로 묶어놓은 파일이다.
    
    Spring Boot 프로젝트에서는 빌드 후 다음과 같은 형태로 생성된다.
    
    ```bash
    ./gradlew build
    ```
    
    생성 결과
    
    ```
    project.jar
    ```
    
    실행 방법
    
    ```bash
    java -jar project.jar
    ```
    
    ---
    
    ## Docker Image란?
    
    Docker Image는 단순히 애플리케이션만 포함하는 것이 아니라 애플리케이션이 실행되는 환경까지 함께 포함한다.
    
    예를 들어 Spring Boot 애플리케이션을 Docker Image로 만들 경우 다음 요소들이 함께 포함될 수 있다.
    
    - Linux 운영체제
    - JDK
    - Spring Boot 애플리케이션(.jar)
    - 실행 설정
    
    이를 통해 서버 환경이 달라도 동일하게 실행할 수 있다.
    
    ---
    
    ## .jar와 Docker Image의 차이
    
    | 구분 | .jar | Docker Image |
    | --- | --- | --- |
    | 포함 내용 | 애플리케이션 코드 | 애플리케이션 + 실행 환경 |
    | Java 설치 필요 | O | X |
    | 환경 의존성 | 높음 | 낮음 |
    | 배포 편의성 | 보통 | 높음 |
    
    ---
    
    ## Docker를 사용하는 이유
    
    ### 1. 환경 차이 문제 해결
    
    개발 환경과 서버 환경이 달라도 동일하게 실행할 수 있다.
    
    ### 2. 배포 편의성 향상
    
    애플리케이션과 실행 환경을 함께 배포할 수 있어 설치 과정이 단순해진다.
    
    ### 3. 유지보수 용이
    
    동일한 이미지를 여러 서버에서 사용할 수 있으며 버전 관리도 쉽다.
    
    ### 4. 확장성
    
    필요에 따라 컨테이너를 여러 개 생성하여 서비스 규모를 쉽게 확장할 수 있다.
    
    ---
    
    ## 정리
    
    .jar 파일은 Java 애플리케이션 자체를 담고 있는 파일이고, Docker Image는 애플리케이션과 실행 환경을 함께 담고 있는 패키지이다.
    
    실제 서비스에서는 환경 차이로 인한 문제를 줄이고 배포를 편리하게 하기 위해 Docker를 활용하는 경우가 많다.
